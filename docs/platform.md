# 小爱 AI 用户前台与管理后台

这是现有音箱路由的可选网页运行模式。旧的 `python main.py` 仍可使用。
网页模式包含设备调度器，不要再启动另一份监听相同设备的旧服务。
本机开发与生产各有独立配置和数据。2026-10-22经用户授权首次部署生产；部署脚本不会由普通本机启动入口自动执行。

## 启动

使用 Python 3.11 或 3.12，安装 `requirements.txt` 后：

```sh
.venv/bin/python -m platform_app
```

浏览器打开 <http://127.0.0.1:8765>。
首次启动生成平台账号 `admin`，随机密码保存在
`deploy/local/platform/bootstrap-admin.txt`（权限 0600），不会输出到日志。
在“账号与安全”修改平台密码后，该文件会删除。
也可首次启动前通过 `PLATFORM_ADMIN_PASSWORD` 指定至少12位密码。

平台账号用于登录控制台，小米账号用于绑定设备，两套账号独立管理。
设备页统一使用“绑定”用语，显示“已绑定”及最近确认结果。
点击“确认绑定状态”先用现有令牌读取小米设备及对话接口，不自动登录、删令牌或发验证码。
有效时无需重新绑定；明确失效才展开“重新绑定当前小米账号”的密码框，账号固定为服务端保存的绑定账号，客户端不能修改。
网络异常显示暂时无法确认，不把它当成密码失效。验证码仅在小米要求时出现。

“更换绑定账号”是独立入口。新账号验证期间旧绑定不变；验证成功后须在5分钟内确认切换。
确认后等待旧账号当前回答结束，再原子替换绑定和设备列表；新设备默认不勾选。
失败、取消、过期或新账号被其他用户占用时保留旧绑定。
切换清空旧设备上下文，保留问答历史和平台用户已用额度；新保存的历史记录附脱敏账号和设备名称。
旧版历史仍保留原记录，不补造此前未记录的账号信息。

平台首次启动读取根目录私有 `config.yaml` 与 `.env` 中的模型配置，符合官方预设地址的现有Key会一次性导入后台加密服务表；后续优先使用网页管理的主备配置，详见下方“模型服务、备用 Key 与后台分类”。旧CLI仍按私有文件运行。平台不自动导入旧的小米账号，
通过“我的设备”由用户主动绑定。验证码只在用户主动绑定时触发；后台恢复连接
遇到额外验证会暂停该账号监听，不自动反复发送验证码。

本机项目附带私有启动文件 `deploy/local/start-platform.command`，其中排除了生产触屏设备。
2026-10-22补充自动打开浏览器：在Finder中双击该文件启动，服务页面就绪后自动打开Chrome（未安装时使用默认浏览器）。
重复启动会打开已运行的本机网页，不新增服务实例；启动失败或45秒内未就绪会提示查看终端，不提前打开错误页面。
启动文件依赖同目录私有辅助文件`open-local-platform.py`，终端中的服务需保持运行。聊天中的文件链接可能仅打开编辑预览，不能视为已执行启动。
正式运行前请确认没有其他环境监听同一台音箱。
通用排除配置为 `PLATFORM_EXCLUDED_DEVICES`，值为逗号分隔的 MiNA deviceID。
服务端会拒绝启用这些设备，不能通过直接调用 API 绕过。

## 用户流程

1. 管理员在“管理后台”创建邀请，通过可信渠道把一次性链接交给用户。
2. 用户设置平台账号、至少12位密码和安全邮箱，完成邮箱验证码后注册。邀请24小时有效；邮箱验证码和密码重置链接10分钟有效且一次性。
3. 登录平台后绑定自己的小米账号，填写小米账号和密码，按页面提示填写短信或邮箱验证码。
4. 首次获取设备默认不勾选，由用户主动选择；刷新网页恢复已保存的选择，刷新设备列表不自动增加勾选。只有点击“确认并更新监听”才开始轮询。
   未验证兼容的机型、明确不支持的音箱和被环境排除的设备显示禁用原因；非音箱设备隐藏。
5. 暂停后不接收新问题，当前已开始的回答允许完成。解绑会等待当前任务结束，再删除绑定凭据。

每个平台用户先绑定一个小米账号，多台设备共享额度；同一个小米账号不能绑定给不同用户。
未知机型不能用默认动作冒险启用。验证码错误后重新验证，60秒内不重复开始绑定。
复杂图形验证等暂不支持，页面提供通用失败提示，不输出小米原始认证响应。

## 额度与对话

- 默认每天50次、每分钟5次、每次最多1024个输出 token，管理员可调整。
- 按北京时间零点重新计算每日额度。模型请求发出即计一次，包括失败和消耗未知的请求。
  在等待队列中的请求先占位；发出前取消会释放额度。
- 设备问答使用个人额度，管理员连接测试计入管理员额度。普通用户不开放网页文字模型调用。平台模型请求并发默认4，后台可调整；每台设备顺序回答，轮询与应答独立运行，一台设备的长播报不会阻塞另一台设备。
- 超限不调用模型，音箱最多每60秒提示一次。供应商返回的 token 与每日次数分别统计。
  未知用量不记为零；符合条件的失败可尝试备用服务，超时等情况不盲目重发，详见主备规则。这里不是人民币账单硬封顶。
- 默认记忆600秒、10轮，按用户和设备隔离；管理员连接测试不使用上下文。
  失败接管模式按小爱原始回答决定是否调用；触发词模式只处理命中关键词的问题。管理员连接测试只发送固定短问题，不走接管判断。保留播报分段之间的1秒余量。
- 模型“已返回”和播报“指令已提交”分开显示，不承诺音箱已完整播放。
- 音箱提示词固定，用户不能覆盖。记忆规则由管理员设置，用户可查看当前生效值、清空单个设备上下文。

## 历史与隐私

问答历史默认保存60天，管理员可设置1至3650天。每小时按时间顺序分批删除到期内容；
缩短期限后，到期记录立即不再展示，下次定时清理从磁盘数据库中删除。
用户可删除单条或全部历史。历史页在可见期间每4秒增量检查新记录，切回标签页时立即检查；新记录加入顶部，保留已加载的旧记录和阅读位置。历史仅供用户查看，不会从数据库自动恢复模型上下文。

账号密码、绑定凭据、问答正文使用 AES-256-GCM 加密，不在日志或管理接口中回显。
平台密码使用带随机盐的 scrypt 哈希。管理员通过管理后台只能查看用量与状态，
没有查询他人问答正文的 API；应用仍需在服务器内存中临时解密以调用模型和播报。
因此，持有服务器及加密主密钥的人不在产品权限隔离的承诺范围内。

数据文件：

- `deploy/local/platform/platform.sqlite3`：账号、设备、规则、用量；小米凭据为密文。
- `deploy/local/platform/history.sqlite3`：加密问答，**不纳入常规备份**。
- `deploy/local/platform.key`：加密主密钥，独立于数据库；丢失后无法解密，请单独保管。

私有运行目录被 Git 和 Docker 构建上下文忽略。生产可通过 `PLATFORM_STATE_DIR`、
`PLATFORM_KEY_FILE` 或启动参数调整位置，密钥不要与数据库备份打包。

## 历史用量导入与备份

先通过邀请建立目标用户，再导入旧 JSONL。重复导入不重复计数，不补造问答正文。

```sh
.venv/bin/python -m platform_app.admin import-usage --username USER --path /absolute/path/usage.jsonl
.venv/bin/python -m platform_app.admin backup --directory /absolute/private/backup-directory
```

备份只包含配置、加密凭据和用量；不包含历史数据库、主密钥、有效登录会话、可信浏览器、验证码、发信队列或邀请。
恢复前先停止平台，恢复 `platform.sqlite3` 和单独保管的原主密钥，再启动。
备份不保留对话历史，故无法通过该备份恢复已删除或到期的对话。

## 邮箱、找回密码与可信设备

平台登录与小米账号绑定独立。注册必须验证安全邮箱，一个邮箱只关联一个平台用户。
平台用户名不区分英文字母大小写：`Test1`、`test1`和`TEST1`代表同一个账号，注册不能重复占用，登录可使用任意大小写。密码仍严格区分大小写。
注册与登录表单均醒目提示上述区别，用户名输入关闭自动首字母大写；页面与邮件保留注册时的显示写法。
数据库以`username COLLATE NOCASE`唯一索引兜底，发注册验证码前和完成验证时均按相同口径检查，私有维护工具按用户名定位账号时也遵循此规则。
已有账号升级不改用户ID、显示名或关联数据；若旧库存在仅大小写不同的重名，启动会提示维护者先确认归属，不会自动合并、删除或任选账号登录。本机升级前只读核对无此冲突，生产本次未部署。
邮箱原文加密保存，唯一键使用主密钥派生的 HMAC；验证码也只保存绑定挑战 ID 的 HMAC。
未验证邮箱不会创建注册用户或授予会话；旧版密码登录产生的会话不再具有网页访问权限。
原有设备监听配置与历史不因补绑邮箱被删除或转移。

SMTP 通过 `PLATFORM_MAIL_CONFIG` 指向权限0600的私有 JSON，格式见
[邮件配置示例](deployment/mail.example.json)。465使用TLS，587使用STARTTLS，始终校验证书并禁止明文认证。
本机默认路径为 `deploy/local/mail.json`。验证码邮件即时发送，失败不给会话；安全通知加密排队，失败最多重试5次，后台重试间隔5分钟。
当前未提供通知投递状态的管理页面，SMTP接收也不保证最终送达收件箱。

旧账号的邮箱归属必须线下确认；不能让持有旧密码的人自行填写邮箱。
在确认后，由服务器维护者执行：

```sh
.venv/bin/python -m platform_app.admin set-recovery-email --username USER --email ADDRESS
```

该命令只允许预设尚无安全邮箱的用户，撤销旧会话。下次登录仍须通过该邮箱验证码才能查看聊天记录。
新安装的admin同样需要通过私有维护流程预设邮箱。已有安全邮箱只能通过原邮箱和新邮箱验证更换。

用户主动勾选“记住这台设备”后，浏览器收到随机HttpOnly令牌，服务端仅存令牌摘要。
重新登录始终要求密码；可信浏览器、浏览器标识、网络位置同时匹配时可免邮箱验证码。
首次或新浏览器，即使IP同城也必须验证。连续多次登录尝试会要求邮箱验证。
上次实际登录超过7天、上次邮箱验证超过30天、可信记录撤销、网络不明或城市变化时重新验证。
普通轮询和打开页面不刷新这些期限。退出登录保留已主动选择的设备信任；账号与安全中可撤销。
密码重置、更换邮箱和退出其他会话会撤销可信设备；修改密码也会撤销全部可信设备。

相同IP可匹配熟悉网络；同城判断须设置 `PLATFORM_CITY_DB` 指向合法获取的MaxMind城市MMDB文件。
只在本机查询，不向外部网站发送用户IP。无城市库、定位不明时不会把两个不同IP认作同城。
城市库授权和更新由部署者维护。客户端自报的IP/城市不作为判定依据。

“忘记密码”使用已验证邮箱，未知邮箱与已注册邮箱返回一致提示；发信在通用响应后处理。
邮件包含平台用户名和一次性重置链接，链接10分钟有效。重发使旧链接失效。
重置会撤销所有会话、可信设备及在途验证，随后须用新密码和邮箱重新登录。
管理员只能发起发送重置邮件，不能从API取得重置链接，也不能借此读取用户历史。
验证码最多尝试5次；发送按邮箱每分钟1次、每小时6次限速，账号登录尝试也有持久限速和IP限速。
用户停用、密码变化、邮箱变化、会话变化等均会在验证完成时重新核对。

更换邮箱、修改密码、更换绑定账号、解绑需10分钟内完成过邮箱验证。
2026-10-22将“更换绑定账号”的前台邮箱验证推迟到点击“验证新绑定账号”提交表单时；打开表单、查看密码找回指引和取消更换不检查或发送邮箱验证码。提交时先清空页面的小米密码框，再按需验证平台安全邮箱；10分钟内已有验证则复用，验证取消/失败不会向小米提交更换请求，取消后须重新输入小米密码。更换请求及最终确认切换仍由服务端检查10分钟有效期，不放宽登录或敏感操作的安全时限。
本次通过31项认证与用户名相关回归，以及合成浏览器的打开/取消不发码、提交才验证、取消验证不提交小米请求、验证后只提交一次及有效期内复用检查；模拟直接绕过前台提交过期请求和确认切换仍被拒绝。没有发送真实邮件或请求真实小米绑定；仅静态前端变更，本机刷新生效，无需重启。
系统在每次成功登录后发送安全通知，包含邮箱验证登录、可信设备免验证码登录和注册后首次登录；时间显示北京时间，附平台账号、验证方式与登录IP。刷新页面、复用现有会话和登录失败不发送成功登录通知。密码修改和邮箱修改另有安全通知。SMTP配置和真实邮件正文不进入日志。

设备归属按MiNA设备ID与接口提供的miotDID别名去重，数据库原子声明归属。
暂停、刷新、设备暂时离线、账号凭据失效不会释放归属；明确解绑或更换账号后才释放。
已被其他用户占用的设备禁用并提示处理，不能直接调用启用API绕过。
迁移发现重复归属时禁用冲突设备，需人工确认，不自动选择任一用户。
去重范围为同一个平台数据库；独立部署环境仍依靠设备排除配置分工。

## 生产 HTTPS

生产必须设置 `PLATFORM_DEPLOYMENT=production` 和固定HTTPS来源；配置示例见
[生产环境变量](deployment/platform.env.example)与[Caddy示例](deployment/Caddyfile.example)。
域名正确解析、80/443端口可用后，Caddy负责证书申请、自动续期与HTTP跳转HTTPS。
参考[Caddy官方自动HTTPS文档](https://caddyserver.com/docs/automatic-https)。
已有Nginx等代理时应沿用现有代理配置该站点，不能抢占端口或覆盖其他应用。

应用保持监听127.0.0.1:8765，不向公网开放该端口；代理转发真实IP及HTTPS协议。
只有 `PLATFORM_TRUSTED_PROXIES` 明确列出的IP或网段可转发来源信息，禁止通配符。
应用拒绝生产HTTP、错误Host、错误Origin，设置Secure Cookie和HSTS；重置邮件只使用固定来源生成链接。
生产域名及证书配置未完成前不能将本机HTTP开发服务直接向公网开放。
本机默认HTTP不设置HSTS或Secure Cookie，保持开发可用。


## 对话设置：失败接管、播报与记忆

前台分成三个区域：

1. **如何调用 AI**：默认失败接管，只有小爱原始回答命中已启用的后台失败话术时才调用模型。
   固定触发词模式仅处理命中关键词的问题，即使小爱失败也不会自动接管。支持1至5个触发词，每个2至20字符；不会改变音箱本身的“小爱同学”唤醒词。
   切换模式或修改触发词记录生效时间，仅处理之后的新问题；不重放已有问答。
2. **回答与播报**：账号默认前缀为 `deepseek回答`，最多12个Unicode字符，首尾空白去除；空值表示完全不加前缀，不能用truthy回退恢复默认值。
   提示词由平台内置规则固定，网页、管理后台和写入API都不开放修改。旧用户与旧平台自定义提示词迁移时移除，触发词附带的配置前缀也不会覆盖网页模式的固定提示词。
3. **对话记忆**：只读展示管理员设置的实际时长和轮数，提供按设备清空上下文；清空不删除历史。后台提供平台默认值及普通用户专属设置，也可恢复继承默认值。

首次升级会移除旧个人记忆覆盖值，保留平台默认记忆设置；此后用户专属记忆值只能由管理员通过后台或管理接口设置。
这些改动只作用于网页平台；旧 `python main.py` 的触发词与配置文件播报前缀仍保持原有工作方式。

### 失败话术来源与边界

初始话术族参考MIT开源项目[xiaomi_ai_llm的UNSUPPORTED_PATTERNS](https://github.com/open-speaker-llm/xiaomi_ai_llm/blob/main/device/native_first_client.sh#L118)，
包含其[失败提示实测记录](https://github.com/open-speaker-llm/xiaomi_ai_llm/blob/main/docs/history/2026-09-06-boot1-fallback-guard.md)中的完整回复。
不会原样使用其宽泛正则；本项目采用完整回复匹配或多个短语同时出现，不执行管理员输入的任意正则。

后台支持新增、编辑、启用/停用、删除及测试已保存的话术。测试与实际运行使用相同判断函数。
完整匹配忽略标点、空格与全半角差异；组合短语必须全部命中，且原始回答规范化后不超过100字符。
没听清、网络连接及设备控制失败有保护性排除规则，不会因为出现失败短语就交给模型。
普通用户的页面与接口不返回后台话术清单。

平台启动保留第三方库的敏感日志禁用，不让服务器默认日志配置重新启用原始认证响应。

当前非固件改造方案不能保证阻止小爱先说失败提示；使用云端问答记录轮询，通常还需等待几个秒。
平台每次读取最多10条近期记录，提取用户问题及小爱原始TTS文字；原始回答只用于内存判断，不额外写入聊天历史或日志。
原始回答连续两秒没有变化后才判断，空回答最多等待15秒，不以空值判失败。
启动前记录、切换模式前记录、超过60秒的旧问题、明显未来时间及重复请求不调用模型。
同时间戳不同请求按请求ID区分，多个设备独立轮询；同一设备以最新有效交互为准，不积压播报过时回答。
正常原生回答和未命中话术不会调用模型，也不占提问次数。实际补答仍受个人额度、频率与设备启用状态限制。
进入模型队列后再次检查模式、话术、设备和过期时间，设置变化可取消尚未发出的请求；已经发出的回答允许完成。
未知话术可能漏判，语义相近的正常短回复仍可能误判；管理员应使用测试区检查新增话术。

### AI 并发与排队

后台“AI 并发与排队”仅管理员可见。`PUT /api/admin/capacity` 保存三个全局参数：

- `model_concurrency`：1至128，默认4；音箱和管理员连接测试共用。
- `queue_limit`：1至5000，默认64；限制尚未生成回答的等待请求。
- `queue_timeout`：1至60秒，默认15秒；包括音箱待答队列与等待模型名额的时间，不是模型生成超时。

配置持久化至本机设置，与用户额度/记忆规则独立，保存后立即生效。提高并发会唤起已有等待请求；降低并发让当前生成完成后再收敛，不取消已开始的调用。缩小队列不会丢弃已经接收的请求，新增请求按新上限处理。已进入等待的截止时间不会因调大设置而延长。

设备轮询与回答拆为独立异步任务。每台设备最多保留1条最新待答；新交互取消旧任务并等待清理后开始下一条，避免上下文或播报并发。全局队列满时跳过新请求；替代问题可复用本设备正在取消的旧等待占位。到期待答直接丢弃。此类问题不会调用模型、不会计入已用提问次数，但用户可能需要重新提问。模型已开始后的失败仍按原额度策略处理。暂停、解绑和更换账号时丢弃未开始的待答问题；当前正在执行的回答按原有规则收尾。重启不恢复队列，避免重播。

后台计数包含正在生成、等待处理、繁忙拒绝和等待超时。`GET /api/admin/capacity` 自动刷新统计，不覆盖正在编辑的配置；累计值从本次进程启动计。统计描述任务状态，不能表示小米网络在线状态或官方服务商保证的容量。

轮询调度通过一次元数据联表查询找出有效设备，状态检查不再解密账号凭据。仍是单进程SQLite，尚未做真实千台音箱压测。离线测试模拟1000条同时到达的请求，仅验证准入上限、队列和动态调整；不证明服务器或小米接口可承受1000台实际设备。

### 后台Token用量排名（2026-10-22，本机已实施）

“Token用量排名”为独立Tab，避免长列表挤占“用户与额度”，默认查看今天，可切换自然日、自然周或自然月并选择过去日期。
另提供“最近3个月”“最近6个月”“最近1年”，为包含截止日期的滚动区间，日期栏随之显示“截止日期”，默认今天，也可选择历史日期。
滚动区间的结束边界为截止日期次日零点，起始边界向前推3、6、12个日历月，遇到目标月无对应日期时取月末；不是固定90、180或365天。
例如截至2026-10-22，最近3个月显示2026-07-23至2026-10-22，最近6个月显示2026-04-23至2026-10-22，最近1年显示2025-10-23至2026-10-22。
当前日期尚未结束时只汇总查询时已经发生的记录；历史截止日期包含当天全部记录，列表和汇总保持相同口径。
所有日期按北京时间解释，周一为一周起点；周期按请求创建时间归属，跨零点完成的主备尝试仍归原请求周期。
默认日期随北京时间跨日更新，手动选择的历史日期保持不变；页面显示完整统计日期范围及最后成功更新时间。

全部平台账号均参与排名，包括管理员、已暂停账号和零用量账号。按已知总Token降序，同分按账号名及用户ID稳定排序。
支持不区分账号名大小写的文字搜索、“仅看存在未知消耗”、每页25人分页；搜索保留全周期原始名次。
普通用户行的“调整额度”切换到“用户与额度”并选中现有用户规则表单，不自动提交，不改变账号状态。
顶部周期汇总不随列表搜索或未知筛选缩小，页面明确说明两者区别。

统计仅包含已发出模型调用的请求，一个问题主备切换多次仍算一个请求。
有模型尝试记录时，输入、输出和总Token分别汇总尝试记录，绝不再叠加请求表中的最终值；
没有尝试记录的旧请求使用原请求用量。失败、空回答或播报中断不排除已返回用量。
缓存是输入分项、推理通常是输出分项，排名不在供应商总Token之外重复累加这些字段，也不从字数估算未知用量。

未知或无效用量不作为真实零消耗：每个请求有已结束但未返回总Token的尝试时标为“存在未知消耗”，
尚在进行且未返回总Token时标为“等待用量返回”；同一问题先失败再等待备用时可同时出现两种提示。
已经返回的部分仍计入已知总Token，输入/输出分项也可能不完整，因此不能把排名当作完整账单或违规结论。
管理员连接测试及旧文字调试纳入相应账号；未发出前取消、纯排队不计入请求次数。
只查询账号基本信息及用量元数据，不读取聊天正文、邮箱、Key或其他凭据；删除聊天历史不会改变排名。

接口：`GET /api/admin/usage-ranking`，只允许管理员访问。
参数：`period=day|week|month|last_3_months|last_6_months|last_year`（默认day）、`reference_date=YYYY-MM-DD`（默认北京时间今天，不能选未来）、
`search`（最长32字符，按字面子串匹配）、`only_unknown`（默认false）、`page`（正整数，默认1）。
返回周期、参考日期、`start_date/end_date`（含结束当天）、时区、`generated_at`、周期`summary`、分页和`rows`。
各用户行含`rank/user_id/username/role/active/requests/prompt_tokens/completion_tokens/total_tokens/unknown_usage/pending_usage`；
摘要含请求数、已知总Token及未知/等待用量的请求数。页大小固定25，越界页收敛到最后一页，空结果仍为第1页。

使用独立单次聚合查询及已发出请求的时间索引，在线程池中读取同一SQLite快照，不逐用户查询、不向浏览器传全部请求。
仅后台该Tab可见时每30秒刷新，切换条件和手动刷新立即查询；旧请求响应不会覆盖新条件或退出后的页面。
只更新排名，不重新填写额度表单。失败保留旧结果和最后更新时间，页面注明结果暂未更新。
本功能不引入成本计价、风险阈值、自动停用、邮件告警或付费功能；生产尚未部署。

本机验证使用临时数据库和模拟账号，覆盖日期边界、权限、主备与未知用量、跨日归属、历史删除及分页；
千用户、两万请求（含一万模型尝试）验证查询与分页，不代表真实生产容量。
独立Chrome桌面/390px手机验证筛选、分页、每30秒刷新、失败保留、滚动和未保存额度草稿；没有真实模型、邮件或音箱调用。

### 模型服务配置

“模型与容量”支持最多20条服务，包含备注名、供应商、模型名、Key、优先级和启用状态。供应商预设为DeepSeek、千问北京/新加坡、OpenAI，使用固定官方HTTPS地址；不开放任意代理地址，避免凭据被误发。千问通过OpenAI兼容协议调用，区域必须与Key相符。Key用现有AES-GCM密钥加密保存，接口只返回末4位；编辑留空保留原Key，换供应商必须填写新Key。写入/删除需要管理员权限和近期邮箱验证。保存不调用模型。

来源：[阿里云OpenAI兼容调用说明](https://www.alibabacloud.com/help/tc/model-studio/model-calling-in-sub-workspace)、[DeepSeek错误码](https://api-docs.deepseek.com/quick_start/error_codes/)。

首次启动将符合预设官方地址的现有DeepSeek/OpenAI配置自动导入加密服务表，仅导入一次。自定义/本地模型保留原配置方式，直到管理员保存首条网页配置。启用网页管理后，停用/删除全部条目不会悄悄回退到环境变量Key。原私有文件暂不删除，便于回滚。

按唯一优先级从小到大选用非冷却服务，每个问题最多尝试3项，复用全平台并发名额；不按Key数量增加并发或额度。401/403鉴权拒绝、429限流、500/502/503服务异常及明确连接失败允许切换；传输超时/504、内容拒绝、参数错误和无有效回复不自动重发。整个尝试链共用原模型超时预算。失败服务暂时冷却（鉴权300秒，其余30秒），之后由真实新请求按顺序恢复尝试；不额外发探测请求。编辑或启停重置该条健康状态，重启也重置健康状态。

故障切换会向备用供应商发送当前问题及上下文，后台说明此行为。`model_attempts`逐次记录服务名、模型、结果与用量，不含Key或问答正文；原始异常不回传。每个问题只占一次用户提问次数；失败尝试未返回用量时，最终成功的总消耗仍标为未知，不将未返回的消耗算成零。历史请求清理通过外键级联清理尝试记录，保留期限与原请求相同。进程中断后，未结束尝试标为interrupted。

管理员接口：GET/POST `/api/admin/model-services`；PUT/DELETE `/api/admin/model-services/{id}`。列表包含最近20次模型尝试，运行状态自动刷新，不覆盖正在填写的Key。


### 打断旧回答（2026-10-21首版）

每台音箱独立维护当前问题ID、时间与回答代次。观察到新的有效用户交互后，先让旧回答作废，再按失败接管/触发词规则判断新问题是否需要AI。新问题尚无小爱回复时也会停止旧流程，不必等待2秒稳定判断；问天气、播放音乐等原生交互同样使旧回答让路，不额外调用模型判定意图。

- 停止口令采用保守整句匹配：停止回答、停止播报、不用说了、别说了、不要说了、闭嘴、停止、停下、暂停、停止播放、暂停播放。允许前置已配置触发词，忽略标点/空格；解释“停止回答是什么意思”不会当成停止。口令只停止旧任务，不占新模型请求。
- 请求ID去重；重复轮询、原回答文字补充、启动/模式切换前记录、超过60秒、明显未来和晚到的更旧记录不会重新取得当前问题所有权。同一批多条只保留最新；同时间戳使用最后新观察到的不同ID。云端没有更细顺序时，不声称知道真实先后。
- 云端兼容TTS与LLM文字；Audio、Action及未知明确类型不触发AI，即使附带文字命中话术或关键词。当前问题后来补出音频/动作类型时，也取消其已启动接管。原生文字仅在内存判断，不写日志或新历史。
- 取消清理涵盖模型等待、生成和播报间隔。每段TTS发出前、异步准备后及模型返回时检查回答代次，阻止作废结果晚到后继续播报；取消不尝试备用服务、不降低服务健康状态。已提交给设备/供应商的请求无法撤销，取消不保证退费。
- 模型未发出释放预留；已发出仍计次数，未知用量保留未知。生成完成保留用户可见的完整加密历史，但播报被打断记为interrupted；用量/运行列表区分“模型已返回”和“播报已中断”，不声称用户听完。未生成完成不保存半份答案。
- 音箱上下文推迟至全部片段提交且估算播报等待结束后写入；中断或提交失败不写入这一轮完整问答。原先已完成的上下文仍保留，这条上下文规则不用于管理员固定短问题的连接测试。最后一段也保留可取消的“字数/语速+1秒”估算等待，避免其提交后立刻视作整轮结束；这仍非硬件完成确认。
- 网页“暂停监听”仍是不接新问题、当前回答允许完成；用户语音主动停止属于另一种行为。没有新增配置开关，不影响其他用户/设备。

本版不主动发送硬件停止/唤醒指令。轮询只能在云端记录可见后发现交互，不能保证收到每条原生停止命令；已发出的那一句可能继续播放或由音箱自身唤醒机制停止。实测Play的立即停止能力另行验证，不能承诺毫秒级打断。旧python main.py不启用平台代次管理。


### 管理员指定服务连接测试（2026-10-21）

普通用户不提供通用文字调试页面、菜单、输入框或接口权限。旧POST /api/debug保留为关闭入口：普通用户403，管理员410，不调用模型、不占额度。已有历史文字调试记录保留；对话记忆页仅能选择真实设备，不再显示调试上下文。
