# 付费服务首版交付说明

日期：2026-10-23。使用人民币、支付宝当面付扫码与微信 Native 扫码，普通直连商户模式。当前没有真实商户资料和正式公网域名，默认关闭收费，不会真实收款或改变既有免费使用规则。测试全部使用临时库、模拟通道和合成签名，不能等同于真实商户联调通过。

## 页面与使用流程

用户菜单“套餐与订单”：查看当前服务、后续待生效服务、套餐、购买/退款说明和本人最近50笔订单。
先绑定小米账号，确认有支持的音箱，再购买。选择套餐和支付方式、阅读同意说明后，后台生成唯一订单与支付二维码。二维码在服务器本地生成，不将付款链接交给第三方图片服务。
付款后页面自动查询，也可手动核对；只有验签通知或验签查单确认成功才能开通。关闭收银窗口不是取消支付，二维码到期也不是确认未扣款；有疑问先核对原订单，不重复支付。

后台独立“套餐与收款”Tab：查看两条支付通道的参数就绪情况，管理最多20个套餐、设置购买/退款规则和联系渠道、明确启用收费、查看每页25笔订单与统计、核对订单、确认全额退款。刷新支付记录保留未保存的配置草稿。商户密钥不在网页填写或回显。

套餐金额、天数和每日AI提问次数由管理员决定；未擅自设置正式售价。演示截图中的价格只属于模拟环境，不是生产套餐。套餐按固定天数（每24小时一天）计算，不是自然月；续购按付款核验顺序接在已有服务之后，不即时升级或叠加当日额度，不自动续费。

启用收费前必须有可用商户参数、上架套餐、购买/退款说明和联系渠道。启用会影响所有普通用户，包括既有普通账号；后台有明确确认。管理员始终免付费限制。关闭收费恢复原额度规则，不撤销已买套餐；已有效套餐仍按其额度使用。现有生产只有管理员且收费保持关闭，本轮不迁移或扣减旧用户权益。

## 权益与成本边界

付款不会自动勾选设备，也不修改账号启停、记忆、触发方式或历史。套餐控制服务期限和每日AI提问次数；既有输出token、每分钟频率、并发/排队限制继续生效。管理员若给用户单独设置更低的每日上限，取该上限与套餐值的较小者。
服务到期可继续登录、查看历史、绑定设备和购买；新的模型请求被拒绝，排队未发出的请求再次检查有效期。已发出的请求允许结束，切备用仍属于同一次请求。音箱的到期提示每设备最多每分钟一次，不额外调用模型。
不承诺无限token、固定人民币模型成本或四小时不限量；失败/中断已发出请求沿用现有计次口径，未知token不按零。退款或删除历史不抹掉已产生的真实用量。

## 订单与支付安全

金额以整数分保存，价格、天数、每日额度和用户同意的说明在创建订单时冻结。价格/权益版本或购买说明改变时，旧页面必须刷新并重新确认。客户端不提交金额、用户ID或“已支付”状态。
订单按用户和客户端幂等键去重；同一订单不会盲目重复下单。每用户每分钟最多创建5笔、同时最多3笔未到期的待支付订单。创建超时记为“结果待核对”，对原订单查单；不谎称支付失败或已成功。
服务端使用独立交易号唯一约束及事务更新订单和权益。重复、并发、延迟的成功通知只发放一次；二维码过期后晚到的真实成功仍予以核验开通，不吞付款。

支付宝使用RSA2请求签名、原始响应片段验签及回调验签，核对应用ID、商户ID、订单号、金额和交易状态。微信使用APIv3请求签名、响应/通知验签（含时间、序列号和公钥匹配）、AES-GCM通知解密，再核对应用、商户、订单、币种和整数金额。未知公钥/签名探测/篡改或重复字段失败即拒绝。
仅两个固定POST回调路径豁免浏览器Origin检查，回调自身必须验签；其他写入仍要求原有来源和会话CSRF检查。回调体同样限长且不接收流式上传。对外网络固定到官方HTTPS接口，校验证书、不跟随重定向、不接受用户指定支付网关。
订单二维码加密保存，普通用户不能读他人订单、查单、二维码或后台数据。接口不包含完整付款身份、商户私钥、聊天正文或原始支付响应；日志不输出原始支付报文或密钥。配置与用量备份包括订单和权益元数据，继续排除聊天库、会话/验证码及主密钥。

## 查单、退款及首版范围

可见支付窗口每4秒检查，服务器限制同一订单最多每10秒向通道核对一次；服务端每30秒处理最多10笔近7天未完结订单，重启后仍可核对。已支付窗口不持续向上游轮询。通道失败保留原数据并标明待核对，不从浏览器“我已付款”直接开通。
管理员全额退款需二次确认、10分钟内邮箱验证及审计记录。退款使用固定退款单号，超时后查询同一笔退款，不自动换号再退；对应权益先挂起，仅核实成功后撤销。重复付款通知不能恢复已退款权益。后续已买套餐原起止时间保留，不自动向前移动。
本版仅支持平台发起的全额退款。微信商户侧发现退款会挂起为“退款待核对”，不能把部分退款当全额退款；商户后台直接部分退款、异常退款、通道明确失败后恢复权益、超过7天的未完结异常等须由维护者按订单与商户记录处理。付款核对入口保留，不能把超时等于退款成功。先完成商户真实小额支付和退款联调，核实运营处理流程后再正式开放。

本版为网页扫码收银，需要手机扫描另一台设备显示的二维码；微信 Native 不承诺同一手机长按/相册识码付款。尚未实现微信H5、公众号JSAPI、小程序或支付宝手机网站拉起；需要对应产品权限后可另接。未加入自动扣款、余额充值、人民币模型成本计价、现金返佣或邀请抵扣金；邀请激励的先前讨论没有被当作已确定财务规则。

## 真实收款接入清单

1. 准备正式域名、公网HTTPS和稳定的生产平台来源，先前的localhost加密隧道只能自测，不能接收支付通知。
2. 在支付宝开通相应商户应用/当面付权限；准备应用ID、收款商户ID、应用RSA私钥与支付宝公钥。当前采用公钥模式，不含支付宝应用证书模式。
3. 在微信商户平台开通Native支付，将AppID与商户号关联；准备商户号、AppID、商户证书序列号、API私钥、APIv3密钥，以及微信支付公钥和对应公钥ID。
4. 参照[支付配置示例](../deployment/payments.example.json)在服务器创建私有文件，设置`PLATFORM_PAYMENT_CONFIG`指向它。配置文件、RSA私钥与APIv3密钥文件必须0600；服务用户可读。APIv3文件只放32字节密钥。不要在聊天中发送私钥，也不要把真实配置放到仓库。
5. 微信公钥映射支持多个ID，轮换时保留仍可能收到通知的公钥；每个通知只使用其序列号对应的可信公钥。更换商户身份不会把旧订单归到新商户，须先处理旧单。
6. 回调地址自动由正式`PLATFORM_PUBLIC_ORIGIN`拼出：`/api/payments/notify/alipay`及`/api/payments/notify/wechat`。代理需转发原始报文和签名头，不能加浏览器登录要求，不能跳转；HTTPS来源/可信代理仍按部署说明配置。
7. 安全重启后确认两通道参数状态、创建正式套餐和购买/退款说明，完成真实小额支付、延迟查询、重复通知、退款及权益核对。参数显示“已配置”不等于通道资质已获批准或真实支付已成功。
8. 确认售价与真实使用成本、客服渠道和退款规则后，由管理员明确启用收费。正式商户联调不可用本项目的模拟接口替代。

## AI 网页应用收款（2026-10-27，本机新增）

新增可选官方 Python SDK 适配器 `WebAlipay`，产品为 `alipay.trade.page.pay`，固定
`FAST_INSTANT_TRADE_PAY`，使用 `page_execute` 生成 POST 表单。浏览器打开实际表单页并提交，
不把 HTML 当作跳转 URL。已有支付宝当面付及微信 Native 配置仍有效；不会自动切换产品或开启收费。

正式商户选择此产品时，在原私有支付配置的 `alipay` 部分指定
`"product": "webpay"`、`"sdk_config_file": "/etc/xiaoai-platform/payments/webpay.json"`。
该独立私有 JSON 须为0600，使用当前同一生产应用的 `appId`、`sellerId`、`appPublicKey`、
`appPrivatePkcsKey`（Python所需PKCS#1原始字符串）和 `alipayPublicKey`。
密钥不带PEM包装，不自行转换或复制沙箱值到生产。加载失败时通道保持不可用。
生产网关固定官方HTTPS，来源仍须通过现有公网域名检查；密钥不经网页填写。

原订单与套餐快照、登录归属、退款审批和权益幂等保持原规则。网页收款新增本人订单的
`GET /api/billing/orders/{id}/pay`、`POST /api/billing/orders/{id}/close`，关单前先查付款状态。
结果页为 `GET /payments/alipay/return`，空参数显示中性说明；带参数时由独立已登录接口校验
完整同步签名并核对本人订单，再向支付宝查询，不能从浏览器参数直接开通。
返回页和付款表单均沿用严格脚本策略，只有付款表单页允许提交到固定官方网关。

异步通知使用官方SDK验签，核对运行配置中的应用/商户、订单及金额；退款事件不当作付款。
通知标识和事件与权益在同一SQLite事务持久去重；重复或冲突事件不能重复发权益。
支付宝查单的官方返回字段不保证有`seller_id`，查询归属依据为绑定应用的SDK请求、
固定官方TLS、响应签名及精确订单号/金额；若响应提供应用/商户字段则额外核对。
未知状态保留待核对；已付订单查询为关闭时挂起人工核对退款，不推断全额到账。
全额退款复用原退款请求号，`fund_change=N`或缺失时保留处理中，退款查询只有明确
`REFUND_SUCCESS`且订单/交易/退款号/金额全匹配才确认成功。

本机单独体验入口：在项目根运行 `.venv/bin/python -m platform_app.alipay_sandbox`，
访问 `http://127.0.0.1:8766/`。只读项目根已校验的`.alipay-sandbox.json`，
从`appIds[0]`选择对应原始字段；固定沙箱网关，无生产回退，也无跳过验签开关。
独立订单保存在被忽略的`deploy/alipay-webpay-sandbox/`，不访问平台账号/聊天，
不监听音箱、不调用模型、不发送邮件、不发放真实套餐权益。
体验金额0.01元属于沙箱资金。浏览器可创建/继续原订单、前往沙箱收银台、查单、关单及全额退沙箱资金；
订单所有权使用HttpOnly浏览器凭据，写入校验固定来源，数据库重启保留，单实例加锁。
本机不传公网`notify_url`，通知处理代码保留，支付结果通过签名主动查询确认。
沙箱买家登录或安卓沙箱支付宝扫码两种方式任选；尚未实际付款不能称为沙箱支付已验证。

查单字段依据：[支付宝官方交易查询契约](https://aipay.alipay.com/docs/vibe-pay/ai-web-app-payment-qianyi/api-list/alipay-trade-query.md)（2026-10-27核对）。
